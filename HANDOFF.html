How should Bragi's new versions be downloadable, given its repo is private?

The factory now gives every desktop app a self-updater. It fetches latest.json and the signed installer with no credential, and GitHub refuses that for a private repo. There are three ways round it. Make Bragi public: the runbook in bragi#244 is ready, and you and the co-contributor pick the day. Publish only Bragi's signed installers to a public releases repo: one more repo, plus a write token in the release job. Ship a GitHub token inside the app: not recommended, because anyone holding the app can extract it. The recommendation is to go public, which needs nothing new. Bragi's updater is built either way; it reaches the Macs once you choose.

Working the backlog to zero, these eight were judged to cost more than they give. Voice editing by phrases such as "scratch that" (#87): idea only, no design. A yes closes all eight, each with its reason. Name any you want kept and it gets built.

Build or drop five features the docs promise but no screen ever reached?

Thoth's product docs describe three: clipboard history, the clipboard as context for AI enhancement, and typing the text instead of pasting it. Bragi stores a ReplayGain setting it never applies, and has a stop-with-fade it never triggers. The unreachable code for Thoth's first two was removed today, since nothing could call it. Typing insertion is hard-coded off. Bragi's two are kept until you say. Building any of them adds a control to Settings, designed in Penpot first. Dropping one removes its lines from the docs.
